# Headless `--screenshot` viewport verification — working recipes

Verified 2026-07-13 against `cahier-de-dictees` (static HTML + 130KB JS SPA) on Linux with the snap chromium at `/snap/bin/chromium`.

## The 4-viewport capture loop

Always test ≥4 widths to catch layout bugs that only appear in narrow bands:

```bash
mkdir -p ~/shots && cd ~/shots
PROFILE_BASE=/tmp/cr-prof
for spec in "360x800" "390x844" "414x896" "768x1024"; do
  IFS=x read -r w h <<< "$spec"
  chromium --headless --disable-gpu --no-sandbox --hide-scrollbars \
    --user-data-dir="${PROFILE_BASE}-${spec}" \
    --window-size="${w},$((h+1500))" \
    --virtual-time-budget=4000 \
    --screenshot="${spec}.png" \
    "http://localhost:8765/index.html" 2>/dev/null
done
ls -la *.png
```

The `+1500` height slack is intentional: chromium captures the full document height, not just the visible viewport, so give it room.

## Sandbox output gotchas

- `--screenshot=<absolute-path>` honors CWD in some sandboxed environments. Symptom: `chromium` says "82030 bytes written" but `ls /tmp/...` can't find the file. **Workaround:** write to `~/shots/` instead of `/tmp/`, or `cd` into the target directory before invoking chromium.
- Each invocation MUST use a unique `--user-data-dir`. Without it, concurrent or back-to-back runs collide on the lockfile.
- `--virtual-time-budget=4000` is the minimum for non-trivial SPAs. Below that, JS init hasn't completed and screenshots show a blank page.

## Screenshotting every tab of a pure-state SPA

Most client-side JS apps don't expose URL-routed tabs (no `location.hash` handling, no `popstate`). Cheap workaround: copy the source, swap the initial state in each copy, render each.

```python
import shutil, os
src = '/home/thomas/Projects/site/index.html'
work = '/tmp/shot-work'
os.makedirs(work, exist_ok=True)

# Tabs that the SPA exposes - find them via grep
import subprocess
tabs = subprocess.check_output(
    ['grep', '-oE', r"currentPage='([a-z]+)'", src]
).decode().split('\n')

for raw in tabs:
    if not raw.strip(): continue
    tab = raw.split("'")[1]
    dst = os.path.join(work, f'{tab}.html')
    shutil.copy(src, dst)
    with open(dst) as f: html = f.read()
    # IMPORTANT: replace_all=False - only the declaration site, not other refs
    html = html.replace("let currentPage='home'", f"let currentPage='{tab}'", 1)
    with open(dst, 'w') as f: f.write(html)

    profile = f'/tmp/cr-prof-{tab}'
    os.system(f'''
        chromium --headless --disable-gpu --no-sandbox --hide-scrollbars \\
          --user-data-dir={profile} \\
          --window-size=390,2400 --virtual-time-budget=4000 \\
          --screenshot=~/shots/{tab}_mobile.png \\
          file://{dst} 2>/dev/null
    ''')
```

## Responsive bug pattern: inline `grid-template-columns` overrides media queries

The 2026-07-13 `cahier-de-dictees` audit found 18 media queries but mobile was broken on the Reports page. Root cause:

```html
<!-- Generated by JS template literal in renderReports() -->
<div class="grid" style="grid-template-columns:1fr 1fr">
  <div class="card">Réussite par catégorie</div>
  <div class="card">Progression de la classe</div>
</div>
```

Inline `style` beats class rules. The page's `.stats`, `.quick`, `.home-side`, `.form-grid`, `.summary` all collapsed correctly at `@media(max-width:700px)` because they were class-only. The `.grid` divs were inline-styled — they did not.

**Fix pattern:**

```css
.reports-grid{display:grid;grid-template-columns:1fr 1fr;gap:18px}
.reports-grid.no-top{margin-top:18px}  /* if you need a margin variant */
@media(max-width:700px){
  .reports-grid{grid-template-columns:1fr!important;gap:14px}
}
```

```html
<div class="reports-grid">         <!-- was: class="grid" style="grid-template-columns:1fr 1fr" -->
<div class="reports-grid no-top">  <!-- was: class="grid" style="grid-template-columns:1fr 1fr;margin-top:18px" -->
```

Search your own code with:
```bash
grep -nE 'style="[^"]*grid-template-columns' index.html
```

Any hit is suspect. Either (a) move to a class with media queries, or (b) wrap in a `@media (min-width:...)` container that hides the parent at mobile widths.

## Grep checklist for mobile-breakage patterns

```bash
# Inline grids that may ignore media queries
grep -nE 'style="[^"]*grid-template-columns' index.html

# Fixed widths / min-widths in inline styles
grep -nE 'style="[^"]*(width|min-width):\s*[0-9]' index.html

# white-space:nowrap in templates (can push past viewport)
grep -nE 'white-space:\s*nowrap' index.html

# width:max-content without overflow-x handling
grep -nE 'width:\s*max-content' index.html
```

## Vision_analyze reliability

On screenshot PNGs, `vision_analyze` sometimes returns:

```json
{"success": true, "analysis": "User Safety: safe"}
```

with no actual description, and no error. This is intermittent — sometimes it works on the second attempt with the same image, sometimes it never returns content. **Do not** treat empty vision output as proof the screenshot is fine, and **do not** treat it as proof it's broken. Strategies:

1. Retry once or twice with identical arguments.
2. If still empty, use `python3 -c "from PIL import Image; ..."` to crop a sub-region (`Image.open(p).crop((0,0,W,1000))`) and re-analyze — sometimes sub-regions work where the full image doesn't.
3. If still empty, fall back to source-level grep + CSS audit. Trust structural verification over vision when vision is uncooperative.
