# Deploy recipe — push to private GitHub repo + publish to Vercel

Captured from the 2026-06-02 run on the Memory vault analysis site. The site
was 8 HTML files + 1 CSS + 1 JS (~106 KB total), generated by
`vault-pattern-mining` and pushed to a private GitHub repo + a Vercel
production deployment.

## 0. Assumed state at start

- `gh` CLI is installed and logged in (`gh auth status` shows
  `✓ Logged in to github.com account <user> (keyring)`).
- The site directory exists at some path (e.g. `/home/thomas/Desktop/vault-patterns/`).
- The site has been verified locally (Phase 5 of `vault-pattern-mining`).

## 1. GitHub side

### 1a. Local init + first commit (if not already a repo)

```bash
cd /path/to/site
git init -b main
git add -A
git commit -m "Initial site: <one-line description>"
```

### 1b. Create private repo + push in one step

```bash
gh repo create <repo-name> \
  --private \
  --source=/path/to/site \
  --remote=origin \
  --description "<one-line description>" \
  --push
```

Slug the name: `vault-hidden-patterns`, not `Vault Hidden Patterns`.

### 1c. Verify

```bash
gh repo view <repo-name> --json name,visibility,url
# Should print: "visibility":"PRIVATE"
```

URL form: `https://github.com/<user>/<repo-name>`.

## 2. Vercel side

### 2a. Install Vercel CLI (if not present)

```bash
npm install -g vercel
# Binary lands at: /home/thomas/.local/lib/nodejs/node-v22.x.x-linux-x64/bin/vercel
```

### 2b. Get vercel on PATH

```bash
export PATH="/home/thomas/.local/lib/nodejs/node-v22.x.x-linux-x64/bin:$PATH"
vercel --version
# Should print: Vercel CLI 5x.x.x
```

This PATH does NOT persist across fresh shells — re-export at the start of
each session, or symlink the binary somewhere on the persistent PATH.

### 2c. CRITICAL: unset VERCEL_TOKEN

```bash
unset VERCEL_TOKEN
```

Why: `~/.bashrc` on the user's machine exports a token value that is a
*literal placeholder* (e.g. `vcp_6N...DljE` with real `...` in the
middle, or a redacted display string with `*` characters). The CLI
silently reads this from env. If it's a placeholder:

- The CLI rejects the auth with confusing "scope" / "invalid token" errors.
- The device-flow login never appears.
- Or, with `--token ***`, the CLI complains:
  `Error: You defined "--token", but its contents are invalid. Must not contain: "*"`
- Or worse, the literal `*` chars get shell-globbed into nothing.

Solution: always `unset VERCEL_TOKEN` before doing anything Vercel-related.

### 2d. Device-flow login

```bash
vercel login <user-email>
```

Output:
```
WARNING! The following arguments are deprecated: <user-email>
> Visit https://vercel.com/oauth/device?user_code=XXXX-YYYY
Waiting for authentication...
```

**Hand the URL to the user.** Tell them: "Visit
`https://vercel.com/oauth/device?user_code=XXXX-YYYY` and click Verify."

The login process is silent until auth completes. Run it in a background
process and wait:

```python
# In Hermes:
terminal(background=true, command="vercel login <user-email>",
         notify_on_complete=true, timeout=600)
process(action='wait', session_id=<sid>, timeout=300)
```

Codes expire in ~5 minutes. If the user is AFK, re-run to get a fresh one.

### 2e. Verify auth

```bash
vercel whoami
# Should print: <username>
```

If you see `Error: Not authorized: ... scope "<x>"`, the env-var trap
fired again. Re-run 2c (`unset VERCEL_TOKEN`) and 2d.

### 2f. Deploy

```bash
cd /path/to/site
vercel deploy --yes --prod
```

Watch for:
```
▲ Production  https://<name>-<hash>-<scope>.vercel.app
▲ Aliased     https://<name>.vercel.app
```

The `Inspect` line points to the Vercel dashboard for this specific
deployment.

The CLI also offers: `> Connecting GitHub repository: ... > Connected`.
Accept it. This wires auto-deploy: every push to main redeploys.

### 2g. Verify

```bash
URL=https://<name>.vercel.app
for path in / /themes/01-<name>.html /assets/style.css /assets/app.js; do
  curl -s -o /dev/null \
    -w "$path: %{http_code}  Size: %{size_download}\n" \
    $URL$path
done
sleep 3
curl -s -o /dev/null -w "stable: %{http_code}\n" $URL/
```

All paths 200, non-zero size, stable after 3s. If any path 404s, the file
isn't in the repo — `git ls-files` to check.

## 3. Pitfalls observed in the 2026-06-02 run

| Pitfall | Symptom | Fix |
| --- | --- | --- |
| `VERCEL_TOKEN` env var is a placeholder | CLI rejects with "scope" or "invalid token" errors | `unset VERCEL_TOKEN` before login |
| Vercel CLI not on PATH | `vercel: command not found` | `export PATH="/home/thomas/.local/lib/nodejs/..."` |
| `*` chars in shell token display | Glob expansion → empty token → confusing errors | Quote: `"$VERCEL_TOKEN"` |
| Device code expired | User took too long | Re-run `vercel login` to get a fresh code |
| Interactive login without email | Hangs forever waiting for browser | Use `vercel login <email>` to force device flow |
| `browser_navigate` to localhost | Times out at 60s | Use curl + `process` polling, not the browser |
| Local dev server still bound | Stale `python3 -m http.server 8765` | `process(action='kill', session_id=...)` |
| `gh repo create` name collision | 422 from API | Pre-check with `gh repo view <name> 2>/dev/null` |
| Wrong team scope | Deploy lands in the wrong Vercel team | Move in dashboard, don't fight the CLI |
| Forgot `--private` | Public repo by default | Always pass `--private` explicitly |
| Build never starts | "Searching for existing projects..." hangs | `unset VERCEL_TOKEN` and retry |

## 4. What "done" looks like

- GitHub: private repo, 1 commit, main branch, URL printed.
- Vercel: production URL + alias URL both 200, all 8 pages + 2 assets
  verified, stable after 3s.
- Auto-deploy: GitHub repo connected to Vercel project (CLI confirms
  "Connected" during deploy).
- Inspection: Vercel dashboard URL printed for the specific deployment.

Hand the user the alias URL: `https://<name>.vercel.app`. That's the one
to share.
