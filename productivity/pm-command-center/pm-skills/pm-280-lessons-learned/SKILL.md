# PM-280: Lessons Learned

Lessons Learned is a Tier 2 closure activity that systematically captures knowledge gained during a project to improve future project performance and organizational maturity.

---

## What Are Lessons Learned?

Lessons Learned are documented insights that capture:
1. **What went well** — successful practices worth repeating
2. **What didn't go well** — problems, failures, or shortfalls
3. **What could be improved** — areas with identified better alternatives
4. **Actionable recommendations** — specific changes for future projects

---

## Prerequisites

Before conducting lessons learned:
```
□ Project is at closure stage (or major phase milestone for large projects)
□ Team members are still available and have fresh memories
□ Sponsor agrees lessons learned is appropriate for this project type
□ Facilitation time is scheduled (allow 1-3 hours depending on project size)
□ Organizational lessons learned repository is accessible
```

---

## Step-by-Step: Conduct Lessons Learned

### Step 1: Prepare for the Session

```
1. Set the session date with at least 1 week notice
2. Invite:
   - Core project team members
   - Key stakeholders
   - Sponsor or sponsor delegate
   - Functional managers (for cross-project insights)
3. Prepare materials:
   - Project summary (scope, schedule, cost, quality summary)
   - Final metrics vs. baseline
   - List of major decisions and changes
   - Risk and issue summary
   - Any positive/negative feedback already received
4. Choose a neutral facilitator (not the PM, if possible)
5. Set ground rules for the session
```

### Step 2: Facilitate the Session

#### Opening (10 minutes)
```
- Thank everyone for participating
- State purpose: improving future projects, not assigning blame
- Review project context and outcomes
- Set expectation: honest, constructive feedback
- Agree on ground rules:
  * No names attached to specific failures (keep it institutional)
  * Focus on systemic improvements, not individuals
  * Be specific and constructive
```

#### Theme-Based Discussion (45-90 minutes)

Use themes to guide discussion:

| Theme | Sample Questions |
|-------|------------------|
| **Initiation & Planning** | Were requirements clear? Was the plan realistic? |
| **Scope & Change** | How well did change control work? Any scope creep? |
| **Schedule & Delivery** | Were timelines achievable? What caused delays? |
| **Cost & Resources** | Was budgeting accurate? Were resources available? |
| **Quality** | Were standards met? Any rework cycles? |
| **Risk & Issues** | Were risks identified early? Did issue resolution work? |
| **Team & Communication** | Was the team engaged? Were stakeholders informed? |
| **Vendor/Procurement** | Did vendors perform as expected? Contract terms adequate? |
| **Tools & Processes** | Did organizational processes support the project? |
| **Leadership & Decisions** | Were decisions made timely? Escalation paths clear? |

#### For Each Theme, Capture:
```
□ What worked well (and why — identify repeatable practices)
□ What did not work well (and the impact)
□ What would you do differently (specific recommendation)
□ Who should own implementing this on future projects
```

### Step 3: Consolidate Findings

Immediately after the session:
```
1. Compile all notes into structured categories
2. Remove any identifying information about individuals (unless positive)
3. Distinguish between:
   - Facts (what happened) vs. Opinions (why it happened)
   - Symptoms (surface issues) vs. Root causes (underlying drivers)
4. Prioritize findings by:
   - High/Medium/Low impact on project outcomes
   - Ease of implementation (quick wins first)
5. Create actionable recommendations with owners
6. Identify which findings should go to organizational process owners
```

### Step 4: Document and Publish

#### Document Format

```
════════════════════════════════════════════════════
          LESSONS LEARNED REPORT
════════════════════════════════════════════════════
Project Name:    [Name]
Project ID:      [ID]
Session Date:    [YYYY-MM-DD]

SECTION 1: PROJECT SUMMARY
────────────────────────────────────────────────────
[2-3 paragraph overview: what was delivered, key outcomes,

SECTION 2: POSITIVE LESSONS (What Worked Well)
────────────────────────────────────────────────────
[Number each lesson. For each, provide:]
LL-P-001: [Title]
  Practice:     [What was done]

  Repeat on:    [Future project types]
  Owner:        [Who ensures it is repeated]

[Repeat for each positive lesson]

SECTION 3: NEGATIVE LESSONS (What Did Not Work)
────────────────────────────────────────────────────

  Issue:        [What went wrong]

  Root Cause:   [Why it happened]

────────────────────────────────────────────────────

  Opportunity:  [What could be better]

```

### Step 5: Close the Loop

```
1. Distribute draft to participants for review (5 business days)
2. Address comments and finalize
3. Submit to organizational lessons learned repository
4. Flag high-priority findings for process owner review
5. Reference lessons learned in future project charters (kickoffs)
6. Follow up at 6 months to confirm recommendations were adopted
```

## Quick Retrospective (1-Hour Version)

When full session is not feasible, use this accelerated format:

```
START (10 min): What should we START doing on future projects?
  - Capture 3-5 items, vote on top 2

STOP (10 min): What should we STOP doing?
  - Capture 3-5 items, vote on top 2

CONTINUE (10 min): What should we CONTINUE doing?
  - Capture 3-5 items, vote on top 3

ACTIONS (30 min): For each voted item:
  - What is the specific change?
  - Who owns implementing it?
  - By when?
```

## Common Pitfalls

- **Blaming individuals instead of analyzing systems** — drives honest input underground
- **Capturing observations without recommendations** — future teams don't know what to do differently
- **Not involving the whole team** — insights are incomplete
- **Filing and forgetting** — lessons learned must be actively referenced
- **Too many lessons** — focus on high-impact findings, not everything
- **Waiting until project end** — capture at milestones, not just closure (memory fades)
- **Not distinguishing fact from opinion** — vague lessons don't drive change
- **Facilitator not neutral** — team holds back honest feedback

---

## Verification Steps

```
1. Confirm lessons learned session was held with adequate participation (≥5 team members)
2. Verify findings are documented in organizational repository
3. Check each negative lesson has an associated recommendation
4. Confirm all recommendations have named owners (no orphan findings)
5. Validate distribution list includes relevant stakeholders
6. Confirm high-priority findings were flagged to process owners
7. Verify new projects are referencing lessons learned at kickoff
```
