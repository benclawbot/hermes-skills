# PM Skill: Issues and Actions Management (pm-170)

Issue and action item management is the operational heartbeat of project execution. Every untracked issue is a risk to the critical path.

## When to Use This Skill

- An issue is identified (blocker, defect, risk event, stakeholder concern)
- An action item is assigned (task, deliverable, follow-up)
- You need to track, escalate, or close items
- Status reports require issue/action summaries
- Sprint retrospectives need action item history

## Workflow

### 1. Log the Issue or Action

Create a structured entry with:
- **ID**: Unique identifier (e.g., ISSUE-001, ACT-001)
- **Type**: issue | action
- **Title**: Short, descriptive name
- **Description**: What happened or needs to happen
- **Priority**: Critical | High | Medium | Low
- **Owner**: Person responsible
- **Status**: Open | In Progress | Blocked | Closed
- **Created**: Date
- **Due Date**: Target closure date
- **Linked Items**: Parent issue, sprint, WBS element

### 2. Assign and Notify

- Assign to owner via PM tool or email
- Set due date with stakeholder agreement
- Link to relevant project artifact (sprint, WBS, requirement)
- For blocked items: identify blocking dependency and owner

### 3. Track and Update

- Daily standup: review open issues/actions
- Update status at each status touchpoint
- Log status changes with timestamp
- Note blockers immediately when they emerge

### 4. Escalate When Needed

Escalation triggers:
- Due date exceeded with no resolution
- Critical/High priority item blocked > 24 hours
- Owner unavailable without coverage
- Resource conflict unresolved > 48 hours

Escalation path:
1. Notify owner and their manager
2. Reassign or reprioritize at project level
3. Escalate to project sponsor if unresolved

### 5. Close and Validate

- Verify the issue is resolved or action completed
- Obtain sign-off from requester or stakeholder
- Document final resolution/answer
- Archive for Lessons Learned reference

## Issue Priority Definitions

| Priority | Definition | Response Time |
|----------|------------|---------------|
| Critical | Project halt, no workaround | Immediate (< 1 hour) |
| High | Major impact on critical path | < 4 hours |
| Medium | Moderate impact, workaround exists | < 24 hours |
| Low | Minor impact, cosmetic | < 72 hours |

## Common Pitfalls

- **Log but don't track**: Issues pile up as "logged" but never updated
- **Assign without due dates**: Items float indefinitely
- **Close without validation**: Issue reopened later
- **Skip escalation**: Let blockers fester instead of escalating
- **No linkage**: Issues float in isolation, not connected to WBS/sprint

## Verification Steps

1. Open issues count matches status report
2. All Critical/High issues have owners and due dates
3. Blocked items have active escalation in motion
4. Closed items have resolution documentation
5. Sprint retrospective has action item history available

## Tools

- PM tool (Linear, Asana, Jira, etc.)
- Project register/spreadsheet
- Meeting notes with action item section
- Status report template

## Exit Criteria

- 100% of open issues have assigned owners
- 100% of open issues have due dates
- No Critical/High issue without daily update
- All closed items have documented resolutions
