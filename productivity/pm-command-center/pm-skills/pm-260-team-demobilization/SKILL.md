# PM-260: Team Demobilization

Team Demobilization is a Tier 3 closure activity that formally releases project team members, completes administrative requirements, and ensures knowledge transfer to ongoing operations or successor projects.

---

## What Is Team Demobilization?

The structured process of:
1. Wrapping up all work assignments for team members
2. Conducting formal performance feedback and reviews
3. Completing administrative paperwork (timesheets, expenses, access)
4. Transitioning knowledge to operations or follow-on teams
5. Formally releasing team members to their parent organizations or new assignments

---

## Prerequisites

Before demobilization begins:
```
□ Project Closure Report approved (or in final review)
□ All deliverables accepted by sponsor/customer
□ Team members have completed all assigned work
□ Knowledge transfer sessions completed
□ Final status report issued
□ Sponsor authorization to release team received
```

---

## Step-by-Step: Team Demobilization

### Step 1: Identify Release Timeline

```
1. Determine the formal release date (coordinated with HR and line managers)
2. Provide minimum notice (typically 1-2 weeks per employment contract)
3. Align release dates with payroll periods if applicable
4. Identify team members with extended notice periods — start process early
5. Notify functional managers of upcoming availability of their staff
```

### Step 2: Complete Work Wrap-Up

```
For each team member, confirm:
□ All assigned tasks are complete or formally transferred
□ Deliverables are in accepted state
□ Documentation is up to date
□ Open issues are reassigned or closed
□ Handover notes prepared for any ongoing responsibilities
□ Access credentials to project systems are documented (for next team)
```

### Step 3: Conduct Knowledge Transfer

```
□ Schedule KT sessions for critical knowledge areas
□ Document:
  - System architecture and key technical decisions
  - Known issues and workaround procedures
  - Configuration details and credentials
  - Contact lists for suppliers and stakeholders
□ Identify who holds critical knowledge (tacit knowledge)
□ Assign buddy or shadow for complex handoffs
□ Record KT sessions if institutional knowledge capture is required
```

### Step 4: Performance Reviews & Feedback

```
□ Conduct formal performance review for each team member
□ Complete project-specific performance assessment
□ Document achievements, challenges, and development observations
□ Provide feedback aligned with organizational performance management process
□ Ensure all timesheets and expense reports are submitted and approved
□ Confirm leave/absence records are up to date
```

### Step 5: Administrative Close-Out

```
□ Retrieve and inventory all project-issued equipment
□ Process expense reimbursements
□ Close project code in time-tracking system
□ Confirm access rights are revoked or transferred
□ Issue project completion certificates or letters (if organizational practice)
□ Update team directory entries (remove project affiliation)
□ Confirm benefits and contracts are properly closed (for contractors/vendors)
```

### Step 6: Formal Release

```
□ Issue formal release notice to each team member
□ Confirm line manager has been notified of availability
□ Conduct team celebration or recognition event (keeps morale positive)
□ Document team performance summary for organizational memory
□ Offer exit interview if applicable
```

## Special Cases

### Contractors and Vendors
```
- Verify contract end dates match release
- Confirm all SOW milestones achieved
- Process final invoices
- Obtain contractor performance feedback
- Complete vendor evaluation forms
```

### Team Members Moving to Operations
```
- Ensure operations counterpart is identified and briefed
- Conduct extended KT sessions
- Assign point of contact for post-project questions
- Schedule check-in at 30/60/90 days post-transition
```

### Early Departures (Resignations During Project)
```
- Coordinate with HR immediately
- Accelerate knowledge transfer
- Reassign critical tasks before departure
- Document tribal knowledge proactively
- Adjust project schedule if necessary
```

---

## Common Pitfalls

- **Releasing team before formal sponsor acceptance** — creates accountability gap
- **Skipping knowledge transfer** — critical tacit knowledge walks out the door
- **Not coordinating with line managers** — creates HR conflicts
- **Forgetting contractor close-out** — auto-renewals or unexpected invoices
- **Equipment not returned** — organizational asset loss
- **No performance feedback** — team members feel unvalued, retention suffers
- **No closure communication** — rumors spread faster than facts

---

## Verification Steps

```
1. Confirm all team members have a signed release or confirmed line manager handoff
2. Verify all project-issued equipment is returned (sign-off inventory)
3. Confirm all timesheets and expense reports are closed in the system
4. Validate all project access credentials are revoked or formally transferred
5. Check that all KT documentation is filed in the project repository
6. Confirm all contractors have been formally closed out (including final payment)
7. Verify HR has updated organizational charts/directory
```
